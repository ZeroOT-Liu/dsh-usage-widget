## 修复

### 未压缩的 `.jsonl` 会话日志不再永久报错

索引会列出 `.jsonl` 与 `.jsonl.zstd` 两种会话文件，但解码器只实现了多帧 Zstandard。遇到未压缩的 `.jsonl` 时，帧扫描器抛出「invalid Zstandard frame magic」，该文件被重置到偏移 0 后下一轮再抛一次 —— 结果是这个文件**永远**统计不到，面板还会一直挂着一条错误诊断。

现在容器格式在建立文件记录时按后缀确定，未压缩文件走行解码器：只消费到最后一个换行，半行留到下一轮，与「尾帧未写完就不解码」的规则完全一致，因此既不会重复计数，也不会把写了一半的记录算进去。任意非 Zstandard、也非 `.jsonl` 的字节仍然按损坏上报 —— 这条路径没有被放宽。

### 余额查询加了超时

余额取自外部平台。之前一次永不返回的请求会把**合并后的那个 promise** 一直挂住，之后每次轮询都排在同一个卡住的调用后面，部件彻底没有数字。现在单次查询有 `balanceTimeoutMs`（默认 10 秒）上限，到点按失败降级，下一轮可以重新尝试。

### 改写日志后缓存不再残留旧数字

日志被整体改写（compaction）时，已解析的分桶会被丢弃。之前只有当本轮又读到用量记录才会让合并缓存失效，于是「改写成一个暂时读不出用量的文件」会让面板继续显示**改写前**的数字。现在所有丢弃分桶的路径都会显式让缓存失效。

### 上报给平台的客户端版本不再漂移

`VERSION` 之前硬编码为 `1.0.0`，与包清单脱节，v1.3 装机后仍向平台自称 1.0.0。现在从 `package.json` 读取；清单读取失败时降级为 `unknown`，不会在导入期抛错。

### 合并缓存有上限

缓存键里含 `sessionId`，而它来自查询参数，键空间由调用方决定。现在 `sessionId` 最多保留 128 字符，合并缓存上限 256 条（超出淘汰最旧的），不再依赖「下次版本号变化时顺带清空」。

## 新增

### 缓存命中率

今日明细里新增「缓存命中率」一行（缓存命中 ÷（未命中 + 命中））。DeepSeek 的缓存命中价格远低于未命中，这个比例直接决定同样 token 量下的花费，之前只能自己拿两个数去估。

### 倒计时真的在走

「距切换」之前只在每次轮询（默认 30 秒）时才更新，看起来像卡住了。现在展开面板时每秒重绘一次，倒计时逐秒递减；数值仍由宿主下发的两个时刻计算，本机时钟或时区不准也不影响。

同一个心跳还会在倒计时归零的瞬间立刻重读一次汇总，所以徽标在切换点就翻档，而不用等下一次轮询。为免本机时钟偏差导致每秒重读，同一边界只会触发一次。

### 键盘可达性

- 展开面板后按 `Esc` 收起（之前只能用鼠标再点一次行）。
- 触发行补上 `aria-haspopup`，与已有的 `aria-expanded` 配对。

### 面板页脚显示版本

更新时间旁显示 `v1.4.0`，方便确认当前装的是哪个版本 —— 之前只能去翻 `package.json`。

## 安装

```bash
dsh plugin --profile desktop add "https://github.com/ZeroOT-Liu/dsh-usage-widget/releases/latest/download/dsh-usage-widget.tgz"
```

**升级后需要重启 Harness**（宿主半边只在进程启动时加载），然后刷新页面（Ctrl+R）。

> 响应新增了 `version` 字段，客户端在半边缺省时不显示版本，其余降级行为不变。
